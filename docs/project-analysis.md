## 1. Project Overview

Epicenter is a full-stack gym management system built as a multi-project Angular 21 workspace with a Firebase backend. It consists of two Angular applications and a set of Firebase Cloud Functions.

### Applications

| App | Target | Description |
|-----|--------|-------------|
| `gym-app` (main, `src/`) | Staff | Internal dashboard for day-to-day gym operations: member management, attendance tracking, POS/store, cash register, inventory, reports, user management, and settings. |
| `members-portal` (`projects/members-portal/`) | Public | Member-facing portal. Currently minimal — a landing page with feature cards and product cards. |

### Architecture Summary

- Angular 21 standalone components (no NgModules)
- Signals for local UI state, RxJS Observables for Firestore data streams
- `inject()` pattern for dependency injection throughout
- Firebase Firestore with persistent local cache and multi-tab support
- Firebase Auth with email/password and custom claims for role-based access
- Firebase Cloud Functions v1 (Node 20) for privileged server-side operations
- Angular Material 21 (MDC-based) for all UI components
- ApexCharts (via ng-apexcharts) for analytics/reporting charts
- Vitest 4 for unit testing

### Routing Architecture

Top-level routes are defined in `src/app/app.routes.ts`. The store feature has its own sub-routes in `src/app/features/store/store.routes.ts`. Most feature components are lazy-loaded via `loadComponent` / `loadChildren`.

All authenticated routes use `authGuard`. Role-restricted routes additionally use `roleGuard` with roles specified in `route.data['roles']`. The `/users` and `/settings` routes use `adminGuard` or `roleGuard` with `['ADMIN']`.

## 2. Data Models & Firestore Schema

### Firestore Collections Map

```
├── members/                    # Member profiles
│   └── {memberId}/
│       └── measurements/       # Sub-collection: body measurements (progress tracking)
├── attendance/                 # Check-in/check-out records
├── products/                   # Store inventory (retail + consumable)
├── transactions/               # POS sale transactions
├── shifts/                     # Cash register shift sessions (with embedded transactions array)
├── inventory_logs/             # Audit trail for all stock movements
├── purchase_orders/            # Supplier purchase orders
├── daily_sales/                # Denormalized daily sales totals (doc ID = YYYY-MM-DD)
├── users/                      # Staff profiles (mirrors Firebase Auth)
├── settings/
│   └── general                 # App-wide settings (monthly quota)
└── system/
    └── settings                # Emergency logout timestamp
```

## 3. Services — Business Logic Layer


### 3.1 AuthService (`core/services/auth.service.ts`)

**Purpose:** Authentication and authorization. Single source of truth for the current user's identity and roles.

**Key Behaviors:**
- Wraps Firebase Auth state into an Observable pipeline: `authState` → Firestore profile fetch → `shareReplay(1)`
- Exposes `userProfile` as a Signal (via `toSignal`) for template consumption
- Computed signals: `isLoggedIn`, `isAdmin`
- `hasAnyRole(roles)` — checks if current user has at least one of the specified roles
- `login(email, password, rememberMe)` — sets persistence (local vs session) then signs in
- `logout()` — signs out and navigates to `/login`
- Emergency logout listener in constructor: watches `system/settings.minAuthTimestamp` and force-logs out if the user's auth time is older than the threshold

**Dependencies:** Firebase Auth, Firestore, Router

---

### 3.2 MemberService (`core/services/member.service.ts`)

**Purpose:** CRUD operations for gym members, membership renewal, and duplicate detection/merging.

**Key Behaviors:**
- `getMembers()` — real-time Observable of all members ordered by name (no limit — intentional for full list streaming)
- `getMembersPage()` — paginated fetch with cursor-based pagination
- `getMember(id)` — single member Observable
- `addMember()` / `updateMember()` — with audit trail (`createdBy`, `lastModifiedBy`)
- `renewMembership(id)` — extends membership by 30 days from current expiry (or from now if expired)
- `renewTraining(id)` — same logic for training expiration
- `isMembershipExpired()` — checks if membership expiration is in the past
- `findPotentialDuplicates()` — client-side duplicate detection using gender+birthday bucketing and Levenshtein distance name similarity
- `mergeMembers(primaryId, secondaryId)` — atomic batch: moves attendance and transaction records to primary, deletes secondary

**Dependencies:** Firestore, AuthService

---

### 3.3 AttendanceService (`core/services/attendance.service.ts`)

**Purpose:** Check-in/check-out operations and attendance history queries.

**Key Behaviors:**
- `getActiveCheckIns()` — real-time Observable of all records with status `'Checked In'`
- `getHistoryByDate(dateStr)` — one-time fetch for a specific date
- `getAttendanceRange(start, end)` — range query for reports
- `getMemberAttendance(memberId)` — last 365 records for a specific member (for calendar/charts)
- `getMemberAttendancePage()` — paginated version
- `getOccupiedLockers(gender)` — returns occupied locker numbers filtered by gender
- `checkIn(member, lockerNumber?)` — validates locker availability and duplicate check-in, creates attendance record with denormalized member data
- `checkOut(recordId)` — updates status and sets checkout time
- `refreshHistory$` — BehaviorSubject that emits after check-in/check-out to trigger UI refreshes

**Dependencies:** Firestore, AuthService

---

### 3.4 StoreService (`core/services/store.service.ts`)

**Purpose:** The largest service — handles products, cart, POS checkout, inventory management, transactions, analytics, and daily sales denormalization.

**Key Behaviors:**

**Products:**
- `getProducts()` / `getProductsPage()` — product listing with pagination
- `addProduct()` / `updateProduct()` / `deleteProduct()` — CRUD with audit trail

**Cart:**
- `cart$` — BehaviorSubject-backed Observable of cart items
- `addToCart()`, `updateCartItemQuantity()`, `updateCartItemPrice()`, `removeFromCart()`, `clearCart()`
- `getCartTotal()` — computed Observable

**Checkout (Atomic):**
- `checkout()` — the core POS operation. Performs a single `writeBatch` that:
  1. Fetches current product states for stock snapshots
  2. Decrements product stock via `increment(-qty)`
  3. Creates `InventoryLog` entries (type: SALE)
  4. Creates a `Transaction` document
  5. Updates `daily_sales` denormalized document
  6. Updates the current shift's embedded transactions array and totals
  7. After commit: refreshes shift state, emits `saleCompleted$` event
  8. Auto-renews membership/training if applicable products are purchased

**Inventory:**
- `logConsumption()` — deducts stock for internal use (consumables)
- `reconcileInventory()` — stock take: compares physical counts to system, adjusts with audit logs

**Void:**
- `voidTransaction()` — atomic batch: reverts stock, marks transaction as VOID, decrements daily_sales, updates shift

**Analytics:**
- `getSalesAnalytics()` — combines transactions and products for top-selling, revenue metrics
- `getTransactions()` — filtered/paginated transaction queries
- `getSalesTotal()` — server-side aggregation using `getAggregateFromServer`
- `getMonthlySalesReport()` — reads from `daily_sales` collection for efficient monthly views

**Admin Utilities:**
- `recalculateDailySales()` — full rebuild of daily_sales from transactions
- `recalculateSalesForDay()` / `recalculateSalesForMonth()` — targeted recalculation
- `migrateDailySalesToLocalDateKeys()` — one-time migration for timezone fix

**Dependencies:** Firestore, AuthService, MemberService, CashRegisterService (via Injector to avoid circular DI)

---

### 3.5 CashRegisterService (`core/services/cash-register.service.ts`)

**Purpose:** Shift/cash register management. Ensures only one shift is open at a time and all cash movements are tracked.

**Key Behaviors:**
- `currentShift$` — BehaviorSubject of the current open shift
- `ensureValidShiftForTransaction()` — pre-validates shift is open and not stale (from a previous day). Opens `StaleShiftDialog` if stale. Prevents multiple dialogs via `isStaleDialogOpen` guard.
- `openShift()` — creates new shift with opening balance. Double-open protection via Firestore check.
- `closeShift()` — sets actual closing balance, calculates discrepancy
- `addCashTransaction()` — atomic update using `arrayUnion` and `increment` for concurrent safety
- `addExpense()` / `addFloatIn()` / `addFloatOut()` — convenience wrappers
- `getShiftSummary()` — returns current shift totals
- `recalculateShiftTotals()` — self-healing: re-derives totals from embedded transactions array, cross-references transaction collection for void status
- `voidTransactionInShift()` — marks a transaction as voided within the shift's embedded array
- `getVoidTransactionShiftUpdates()` — pre-calculates shift updates for atomic batched void operations
- `getShiftHistory()` / `getShiftHistoryPage()` — paginated shift history

**Dependencies:** Firestore, StoreService, MatDialog

## 5. Core Infrastructure

### 5.1 Animations (`core/animations/animations.ts`)

Three reusable animation triggers:

| Trigger | Type | Description |
|---------|------|-------------|
| `fadeIn` | `:enter` | Fade in + slide up (10px) over 300ms ease-out |
| `slideInOut` | `* <=> *` | Route transition: outgoing slides left + fades, incoming slides in from right |
| `staggerList` | `* => *` | Staggered list entry: each item fades in + slides up with 50ms delay |

Used across most feature components for page transitions and list rendering.

---

### 5.2 Constants

**`commendations.ts`:**
- `SALES_COMMENDATIONS` — 10 motivational messages shown after POS sales
- `CHECKIN_COMMENDATIONS` — 10 messages shown after member check-in
- `CHECKOUT_REMINDERS` — 10 reminders shown after member check-out
- `getRandomCommendation(type)` — returns a random message by type

**`staff-reminders.ts`:**
- `STAFF_REMINDERS` — 35 reminders across 3 priority levels (CRITICAL, IMPORTANT, ROUTINE)
- Covers safety, hygiene, maintenance, hospitality, and social media tasks
- Used by `StaffRemindersComponent` which rotates reminders every 60 seconds

---

### 5.3 Guards (`core/guards/`)

| Guard | Type | Logic |
|-------|------|-------|
| `authGuard` | `CanActivateFn` | Checks Firebase Auth state. Redirects to `/login` if not authenticated. |
| `roleGuard` | `CanActivateFn` | Reads `route.data['roles']`, checks against user's Firestore profile roles. Shows snackbar on denial. Redirects to `/`. |
| `adminGuard` | `CanActivateFn` | Synchronous check via `authService.isAdmin()` signal. Shows snackbar on denial. |

All guards use the functional `CanActivateFn` pattern (no class-based guards).

---

### 5.4 Utils (`core/utils/`)

**`date.utils.ts`:**
- `getLocalDateString(date)` — returns `YYYY-MM-DD` string in local timezone

**`cash-register.utils.ts`:**
- `calculateVariance(shift)` — actual - expected closing balance
- `getVarianceType(variance)` — returns `'balanced'`, `'shortage'`, or `'overage'`
- `calculateNetCashFlow(shift)` — (sales + float in) - (expenses + float out)
- `getShiftAnalytics(shift)` — full analytics object with counts per transaction type
- `filterTransactionsByType(transactions, type)` — filters embedded transaction array
- `formatShiftDate(timestamp)` — handles both Firestore Timestamp and plain Date

### 5.5 Core Components (`core/components/`)

**QuotaStatusWidget:**
- Sidebar widget showing monthly revenue vs quota and daily target

### 5.7 Shared Directives (`shared/directives/`)

**PreventDoubleClickDirective:**
- Selector: `[appPreventDoubleClick]`
- Throttles click events by disabling the element for a configurable duration (default 2000ms)
- Emits `throttledClick` output event
- Used on the POS checkout button to prevent duplicate transactions

## 6. Firebase Cloud Functions (`functions/src/index.ts`)

All functions are Firebase Cloud Functions v1 (HTTPS Callable), protected by ADMIN role check via custom claims.

| Function | Purpose | Security |
|----------|---------|----------|
| `createStaffAccount` | Creates Firebase Auth user + Firestore profile + custom claims | ADMIN only |
| `updateStaffAccount` | Updates Auth user (password, displayName) + custom claims + Firestore profile | ADMIN only |
| `toggleStaffStatus` | Enables/disables Auth user + updates Firestore `isActive` flag | ADMIN only |
| `emergencyLogoutAll` | Revokes all refresh tokens (paginated), sets `system/settings.minAuthTimestamp` | ADMIN only |
